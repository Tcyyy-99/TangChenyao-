# 一、前期准备

### 1\. 工具与资源准备

- **Unity 软件**：安装 Unity 2021\.3 LTS 版本（推荐 LTS 版本保证稳定性），初始可先安装 Windows（UWP）和 WebGL 平台模块（后续可通过 Unity Hub 添加其他模块）。

- **模型资源**：从可靠的模型网站（如 Unity Asset Store、TurboSquid 等）购买变压器三维模型，确保模型包含基本部件（铁芯、绕组、油箱等），格式兼容 Unity（如 FBX、OBJ）。

- **辅助工具**：Figma（用于界面设计）、Excel（整理数据映射关系）。

### 2\. 数据收集与整理

- 整理变压器基础参数（型号、额定电压等）、实时运行数据接口文档（由数据提供方提供，明确数据格式、更新频率）、历史故障记录（至少 3\-5类典型故障案例）。

### 2\. 动画制作

- **基础动画**：针对运维展示需求制作简单动画，如变压器柜门打开（展示内部结构）、冷却风扇转动。

    - 选中模型部件，添加 Animator 组件，创建动画控制器（Animator Controller），录制关键帧动画（Window→Animation）。

- **数据驱动动画**：将实时数据与动画关联，例如当油温超过阈值时，触发 “高温预警” 动画（如模型表面变红闪烁）。

    - 编写简单脚本：通过接收数据值，控制动画参数（如`animator.SetBool("HighTemperature", true)`）。

# 三、软件系统框架搭建

### 1\. 信息架构设计（通用平台思路）

- 确定核心功能模块：设备概览（显示变压器整体状态）、实时监测（展示电压、温度等数据）、故障诊断（显示故障类型及建议）、历史数据查询。

- 模块关系：通过顶部导航栏切换模块，数据在各模块间共享（如实时监测数据同时用于故障诊断分析）。

### 2\. 信息可视化实现

- **数据与模型绑定**：在 Unity 中创建 UI 文本、图表（使用 TextMesh Pro、Unity Chart 插件），编写脚本将接收的实时数据赋值给 UI 元素。

    - 例：将 “绕组温度 = 85℃” 显示在模型旁的文本框，同时用颜色渐变（蓝色→红色）在模型绕组表面标注温度分布。

- **故障诊断展示**：当检测到故障时，在界面弹出故障卡片（包含故障类型、发生时间），同时在模型上高亮故障部位（如绝缘故障时，绕组模型闪烁黄色）。

### 3\. 界面设计与统一风格

- 用 Figma 设计基础界面框架：左侧导航栏（功能模块入口）、顶部状态栏（显示时间、设备在线状态）、主内容区（左侧模型展示，右侧数据面板）。

- 定义 3\-5 个主色调（如电力行业常用的深蓝色、浅灰色）、统一字体（如微软雅黑），将设计好的界面导出为图片，在 Unity 中用 UGUI 还原（创建 Image、Button 等组件匹配设计稿）。

- 确保界面元素尺寸、间距一致（如按钮高度统一为 40px），方便后续应用到其他设备显示屏。

# 四、测试与部署

### 1\. 功能测试

- 模拟数据测试：用随机数脚本模拟实时数据，检查是否能正常显示、动画是否随数据变化（如温度升高时颜色变化正确）。

- 故障场景测试：手动触发历史故障数据，验证故障诊断模块是否能准确识别并展示故障信息。

### 2\. 部署发布

- 根据需求选择发布平台：

    - 本地使用：Build Settings 选择 Windows，导出\.exe 文件。

    - 网页访问：切换到 WebGL 平台，发布后上传至服务器，通过浏览器访问。

- 发布前检查：降低模型面数（Window→Analysis→Profiler 检测性能，面数控制在 10 万以内避免卡顿）、压缩纹理（Texture Import Settings 中设置压缩格式）。

# 五、关键注意事项

- 模型购买后若尺寸不符，可通过 Unity 的 Measure 工具（需安装 ProBuilder 插件）测量实际比例后调整。

- 数据接口若后期变更，只需修改数据接收脚本（保持 UI 绑定逻辑不变），无需重构整个系统。

- 界面设计文件（Figma 源文件）需存档，后续公司其他界面可直接复用颜色、组件样式。

按以上步骤推进，可优先完成核心功能（模型展示 \+ 实时数据可视化），再逐步完善动画和故障诊断细节。
