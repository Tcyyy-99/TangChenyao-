# 模拟经营游戏UX设计方法论

> 模拟经营游戏的交互设计，本质是设计**"信息到决策"的转化路径**

---

## 核心命题

模拟经营游戏天然携带大量数据——资源存量、系统状态、生产效率、因果关系。同样是100条信息摆在玩家面前，有的游戏让人觉得"下一步该做什么很清晰"，有的游戏让人觉得"不知道从哪看起"。

**核心结论**：好的模拟经营交互设计，是让玩家在面对复杂系统时，感受到的不是"被数据淹没的无力"，而是"手握充分信息的从容"——复杂性依然存在，但它不再是阻碍，而是可以被驾驭的对象。

---

## 一、认知负荷理论视角

### 核心问题
玩家在模拟经营中：
- **信息获取时间** >> **操作执行时间**
- 决策质量取决于"信息消化"而非"操作流畅"

### 设计目标
**降低认知负荷，提升信息可操作性**

---

## 二、信息架构设计

### 2.1 信息分层模型

| 层级 | 定义 | 特征 | 示例 |
|------|------|------|------|
| **信号层** | 唤醒注意 | 高视觉权重、含义明确、频率可控 | 红色高亮队列、警告弹窗 |
| **上下文层** | 理解因果 | 解释"为什么"、暗示"怎么做" | 满意度面板、异常说明 |
| **深度数据层** | 精确分析 | 精确数据、历史趋势、供主动查询 | 生产统计、管道流量 |

### 2.2 层级原则
- **信号层**：每条信息需暗示行动方向
- **深度数据**：放置在2-3级菜单，由用户主动触发
- **层级混乱**是常见问题：深度数据闯入信号层 = 噪音

---

## 三、渐进式披露策略

### 3.1 时机判断标准
**"刚好需要" = 玩家首次遇到该信息能解决问题之时**

### 3.2 三种策略

| 策略 | 适用场景 | 案例 |
|------|----------|------|
| **事件驱动** | 低门槛、叙事化 | 《潜水员戴夫》《东方夜雀食堂》 |
| **关卡制** | 中门槛、精确控制 | 《双点医院》《双点博物馆》 |
| **科技树** | 高门槛、自控节奏 | 《缺氧》 |

---

## 四、空间化信息设计

### 4.1 核心原则
**信息应锚定于其描述的对象**

| 方案 | 说明 | 案例 |
|------|------|------|
| **覆盖层** | 空间上叠加数据维度 | 《缺氧》温度/气压层 |
| **上下文面板** | 点击对象就地展示决策信息 | 《双点医院》员工面板 |
| **建造预览** | 操作前展示效果反馈 | 《双点博物馆》放置预览 |

### 4.2 认知成本对比
- ❌ 面板与场景分离：视线反复跳转
- ✅ 覆盖层/上下文面板：信息不脱离空间

---

## 五、因果关系呈现

### 5.1 问题本质
因果链越长，玩家"发现→定位原因"的交互步骤越多

### 5.2 三种解法

| 方法 | 原理 | 适用对象 |
|------|------|----------|
| **面板内嵌跳转** | 逐层向上追溯因果 | 大众产品 |
| **覆盖层切换** | 多维度观察，用户自行建模 | 核心玩家 |
| **直接标注** | 箭头/引线显式连接因果 | 离散决策 |

### 5.3 能力边界
- ✅ 提供探索工具 + 关键节点因果提示
- ❌ 替代学习过程 + 简化到失真

---

## 六、设计决策框架

```
目标受众定位 ─────────────────┐
                              │
     ├─→ 大众产品 ──→ 核心因果显性化
     │                        │
     └─→ 核心玩家 ──→ 探索工具 + 保留发现乐趣
```

## 具体游戏案例深度UX分析

---

## 一、《缺氧》(Oxygen Not Included)

**定位**：高复杂度系统工程型模拟经营

### 1.1 信号层设计

**优点**：
- 复制人死亡 → 最高优先级信号，点击直接跳转镜头
- 资源耗尽警告 → 清晰的状态表达

**问题**：
```
基地全景时：温度异常 + 种植异常 + 复制人死亡 + 建筑损坏
                ↓
        多信号同时弹出 = 注意力被分散 = 实际无信号
```

**UX问题**：信号过载，缺少优先级排序或聚合机制

### 1.2 覆盖层设计（优秀典范）

| 覆盖层 | 呈现内容 | 决策价值 |
|--------|----------|----------|
| 温度 | 基地热力分布 | 一眼定位过热区域 |
| 气体 | O2/CO2/污染气温分布 | 气流走向可视化 |
| 功率 | 电网负载热力 | 一眼识别超载建筑 |
| 病虫害 | 作物感染区域 | 快速定位问题 |

**核心优势**：信息始终锚定在空间上，不脱离场景

### 1.3 渐进式披露问题

```
开局即激活的系统：温度、气压、气体成分、水循环、食物腐烂
                                    ↓
                新手尚未学会挖掘，温度已在影响作物
```

**结论**：对新手不友好，但符合其"工程型玩家"定位

## 二、《双点医院》/《双点博物馆》

**定位**：低门槛大众化模拟经营

### 2.1 信号层设计（优秀）

```
诊室排队过长 → 队列自动变红
                      ↓
            玩家感知"这里需要更多诊室"
                      ↓
            理解即可行动，无需解读
```

**UX原则**：**感知即理解，理解即可行动**

### 2.2 上下文面板设计（标杆）

点击诊室面板显示：

| 信息类型 | 具体内容 |
|----------|----------|
| 当前状态 | 诊治速度、排队人数、当前病人 |
| 异常原因 | 等待时间过长原因说明（标红） |
| 操作入口 | 升级/调整/拆除按钮 |

**关键**：三类信息共处一面板，无需跳转

### 2.3 渐进式披露（关卡制）

| 关卡 | 披露内容 | 认知阶段 |
|------|----------|----------|
| 1 | 基础诊断、药品购买 | 学会看病流程 |
| 2 | 员工招聘、科室扩展 | 学会人力资源 |
| 3 | 治疗室、特殊科室 | 学会进阶系统 |
| ... | ... | ... |

**优势**：设计者精确控制每关信息量，通关=已消化

## 三、《城市天际线》(Cities Skylines)

**定位**：大尺度城市建设模拟

### 3.1 信号层问题

后期面板呈现：
```
交通、犯罪、教育、医疗、噪音、污染、消防...
                ↓
        "数据都有了，但该看哪层？"
```

**问题**：信息过载但缺乏行动指向

### 3.2 覆盖层设计

| 覆盖层 | 用途 | 问题 |
|--------|------|------|
| 交通量 | 识别拥堵路段 | 只能看"堵不堵" |
| 污染 | 识别污染源 | 无法直接定位"谁在污染" |
| 医疗覆盖 | 识别盲区 | 只能看结果，无法追溯原因 |

**结论**：覆盖层提供"观察维度"，但不解释因果

### 3.3 问题诊断困境

```
居民投诉"幸福度低" 
        ↓
打开面板：教育不足 + 医疗不足 + 娱乐不足 + 噪音污染
        ↓
无法判断：哪个是主因？先解决哪个？
```

**UX缺失**：缺少因果优先级提示

---

## 四、《东方夜雀食堂》

**定位**：低门槛叙事驱动模拟经营

### 4.1 事件驱动渐进（优秀案例）

| 阶段 | 新增内容 | 出现方式 |
|------|----------|----------|
| 前期 | 普通食客点餐 | 自然发生，无需教学 |
| 中期 | 特殊食客 | 剧情触发，伴随新食谱 |
| 后期 | 音乐小游戏 | NPC引导解锁 |
| 后期 | 魔法增益 | 事件解锁 |

**核心优势**：学习感低，信息伴随叙事自然流入

### 4.2 对比《缺氧》

| 维度 | 《东方夜雀食堂》 | 《缺氧》 |
|------|------------------|----------|
| 披露驱动 | 事件/剧情 | 科技树/物理模拟 |
| 玩家控制 | 较低 | 高 |
| 新手友好度 | 高 | 低 |
| 系统深度 | 中 | 高 |

---

## 五、《幻兽帕鲁》(Palworld)

**定位**：生存+建造+收集

### 5.1 信息可行动性问题

```
基地效率低 → 原因可能：
    ├─ 动线不合理
    ├─ 帕鲁心情低落
    ├─ 食物供给不足
    └─ 路径过长
                ↓
        状态信息分散在各个体面板
                ↓
        缺少汇总诊断视角
```

**UX问题**：信息存在但可行动性低

### 5.2 对比《双点医院》

| 游戏 | 效率低时 | 玩家行动 |
|------|----------|----------|
| 《双点医院》 | 队列变红+原因说明 | 直接知道"加诊室" |
| 《幻兽帕鲁》 | 显示效率低 | 需逐个排查可能原因 |

## 七、设计改进建议

### 针对《城市天际线》
```
当前：多覆盖层 + 详细面板，但无因果提示
建议：添加"问题根源分析"功能
      例：点击"幸福度低" → 自动展示因果链
          "幸福度低 ← 医疗覆盖不足 ← 医院数量不足"
```

### 针对《幻兽帕鲁》
```
当前：个体信息分散，缺少汇总
建议：添加"基地健康度"仪表盘
      例：一键诊断：动线/心情/饱食度/效率
          每个维度提供"一键修复"建议
```

### 针对《缺氧》
```
当前：开局信息过载
建议：添加"教程模式"开关
      启用时：延迟激活温度/气体等高级系统
      关闭时：保留硬核体验
```

## 总结

| 设计维度 | 核心问题 | 解决方案 |
|----------|----------|----------|
| **信息分层** | 信息vs决策脱节 | 信号/上下文/深度数据三层架构 |
| **披露时机** | 新手期信息过载 | 渐进式披露三策略 |
| **空间位置** | 场景-面板跳转成本 | 覆盖层 + 上下文面板 |
| **因果呈现** | 因果链追溯困难 | 面板跳转 / 覆盖层 / 直接标注 |

**最终目标**：让玩家感受"手握充分信息的从容"，而非"被数据淹没的无力"。
