# PC/主机双端游戏UX设计方法论

> 以《荒野行动·曙光》G83PS4为例，解析跨平台移植的设计密码

---

## 核心命题

> 主机游戏的"简洁"不等于"简单"，而是在**有限操作能力下**实现**高效的交互效率**。

---

## 一、双端适配策略框架

### 1.1 核心挑战

| 维度 | PC端 | 主机端 |
|------|------|--------|
| 操作方式 | 鼠标+键盘（精准） | 手柄（方向输入） |
| 焦点形式 | 光标（自由移动） | 部件状态（线性移动） |
| 功能承载 | 可复杂 | 需简化 |

### 1.2 三种适配策略

| 策略 | 特征 | 适用场景 |
|------|------|----------|
| **完全一致** | 双端功能/布局完全相同 | 简单功能 |
| **基本一致** | 功能/布局统一，手柄优化 | 主流场景 |
| **重构** | 根据平台重新设计 | 差异过大 |

### 1.3 G83PS4策略选择

```
目标：双端功能基本一致 + 布局基本统一 + 手柄操作便利

关键原则：
1. 需求阶段就考虑主机适配性
2. 发现问题立即向策划反馈
3. 不要侥幸"移植时再说"
```

## 二、PC端设计要点

### 2.1 界面布局规范

#### 系统层级原则
- 优先采用"层层深入"形式
- 单个界面内避免多层级
- 层级上限：建议不超过4层

#### 通用框架
```
┌─────────────────────────┐
│     顶部导航栏           │  ← 左对齐/居中
├─────────────────────────┤
│                         │
│      中部内容区          │  ← 核心交互区域
│                         │
├─────────────────────────┤
│     底部键位提示         │  ← 位置灵活
└─────────────────────────┘
```

### 2.2 排版设计原则

#### 线性排列优先

| 布局类型 | 主机友好度 | 说明 |
|----------|------------|------|
| 线性排列 | ★★★★★ | 焦点快速移动 |
| 区域分离 | ★★☆☆☆ | 需返回列表遍历 |

#### 部件靠近原则

```
反例：物品列表 ←→ 制造按钮（距离过远）
正例：制造按钮 + 物品列表 = 操作区（集中）
```

#### 避免下拉式父子级

```
问题：父级悬停即展开子级 → 移动效率低
解绑方案：选中 ≠ 展开，预留展开键位
```

### 2.3 部件状态设计

| 状态 | 触发条件 | 常见遗漏 |
|------|----------|----------|
| 常态 | 默认显示 | - |
| 悬浮态 | 鼠标悬停 | 嵌套部件 |
| 按下态 | 点击/按下 | - |
| 选中态 | 右键菜单 | 右键菜单场景 |
| 禁用态 | 不可操作 | - |

### 2.4 快捷键设计

#### 操作连贯性原则

| 原则 | 说明 | 反例 |
|------|------|------|
| 设备一致性 | 避免键鼠频繁切换 | Esc返回需切换鼠标 |
| 认知负担 | 记忆成本不能过高 | 冷门键位 |
| 操作效率 | 减少步骤 | 需切换设备的操作 |

### 2.5 适配规则

#### 基础框架适配

```
导航栏 + 操作栏：横向自适应，贴边适配
内容区：边距恒定，随尺寸变化
```

#### 部件适配规则

| 适配方式 | 适用场景 |
|----------|----------|
| 贴边适配（固定） | 左/右对齐、左右布局 |
| 贴边适配（自适应） | 通屏列表 |
| 居中适配（固定） | 居中布局 |
| 居中适配（自适应） | 内容居中，背景自适应 |

## 三、主机端移植要点

### 3.1 走焦规则设计

#### 焦点状态模型

| 关系类型 | 场景 | 行为 |
|----------|------|------|
| **同步** | 父子级同界面 | 悬停即选中，子级内容切换 |
| **异步** | 父子级不同界面 | 悬停不选中，需确认键跳转 |

#### 移动规则

| 规则 | 说明 |
|------|------|
| 移动单位 | 一次一格 |
| 加速 | 长按十字键/摇杆加速 |
| 移动范围 | 区域内可交互部件 |
| 初始位置 | 必须在设计文档中明确！ |

#### 特殊情况处理

| 场景 | 规则 |
|------|------|
| 末尾循环 | 需明确定义 |
| 未填满末行 | 焦点移至末行最后一个部件 |

#### 父子级切换模式

| 模式 | 进入子级 | 返回父级 |
|------|----------|----------|
| 模式一 | O键 | X键 |
| 模式二 | 十字键→ / L3 | 最左侧← / L3 |

**注意**：模式二需在最左侧施加操作缓冲

#### 区域间切换

```
边缘跨区：十字键/L3，焦点默认新区域第一格
快速切换：R3直接切换，焦点默认新区域第一格
```

### 3.2 键位适配规范

#### 键位功能映射

| 按键 | 功能 | 说明 |
|------|------|------|
| **O键** | 确定/进入 | SIEA/SIEE固定，SIEJA可自定义 |
| **X键** | 返回/取消 | 弹窗关闭 |
| **▲键** | 检视/详情 | 次要功能补充 |
| **■键** | 补充功能 | 无特定语义 |
| **十字键/L3** | 移动焦点 | 长按加速 |
| **R3** | 浏览/翻页/切换 | 上下浏览/左右切换 |
| **L1/R1** | 一级Tab切换 | 可循环 |
| **L2/R2** | 二级Tab切换 | 可循环 |
| **触摸板** | 打开地图/全屏 | 注意Win系统兼容性 |
| **OPTIONS** | 打开设置 | 约定俗成 |

#### 长按使用场景

| 场景 | 目的 |
|------|------|
| 二次确认 | 替代PC端确认弹窗 |
| 重要功能 | 防止误操作 |
| 支付行为 | 充值/购买 |
| 功能补充 | 短按键位不足时的补充（慎用） |

#### 键位摆放规则

```
通用部件：键位靠近操作区
主要功能按钮：键位直接添加在按钮上
次要功能：显示在底部"按键提示区"
PC快捷键：直接替换为主机键位
```

### 3.3 TRC规则（设计相关）

| 规则 | 要求 | 设计影响 |
|------|------|----------|
| **安全区** | 重要内容在90%×90%范围内 | 边缘留空 |
| **加载** | >30s动画，>60s进度条 | Loading界面 |
| **用户名** | 完整显示16字符Online ID | 预留字符空间 |
| **队伍邀请** | 使用系统邀请功能，≤1次跳转 | 禁用自定义邀请 |
| **关闭游戏** | 使用系统关闭方法 | 禁用自定义退出 |

## 四、焦点设计深度解析

### 4.1 焦点基础概念

| 概念 | 定义 |
|------|------|
| **焦点** | 玩家操作的起点，指向操作对象 |
| **走焦** | 控制焦点移动的操作 |
| **获焦** | 控件从无焦点转为有焦点 |
| **失焦** | 控件从有焦点转为无焦点 |
| **焦点组** | 按功能分区归类的走焦单元 |
| **跨焦点组** | 焦点从组A进入组B |

### 4.2 焦点设计原则

#### 1. 提供初始
```
判定规则：
├── 层级优先：最高层级界面优先
├── 内容优先：上→下，左→右
└── 核心操作优先：核心功能预设
```

#### 2. 可遍历
```
所有可交互元素需可被焦点到达
（可通过键位映射提高效率）
```

#### 3. 焦点唯一
```
同一界面仅一个焦点
跨焦时原焦点需失焦
```

### 4.3 焦点样式设计

#### 基本要求

| 要求 | 实现方式 |
|------|----------|
| 辨识度高 | 放大/边框/底板高亮/循环动效 |
| 形态自适应 | 根据控件尺寸/形态调整 |
| 视觉统一 | 主题色/符号等通用元素 |

### 4.4 走焦顺序规则

#### 就近原则
```
移动方向 + 最近控件 = 目标焦点
（需加入权重系统影响X/Y比重）
```

#### 十字运动原则
```
焦点移动方向 = 用户预期方向
左摇杆/十字键操作兼容
```

#### 焦点记忆路径
```
无记录：按行移动，默认行首
有记录：回到记录路径
                ↓
适用：侧边多层结构 / 固定区域屏外延伸
```

### 4.5 常见走焦场景

| 场景 | 运动方式 |
|------|----------|
| 同行/列移动 | 判断方向上最近卡片 |
| 跨行移动 | 首尾卡片自动跳转下一行首 |
| 非整列节点 | 就近原则 |
| 屏外延伸 | 焦点固定，内容位移 |
| 同屏多层 | 侧边栏结构 |
| 跨页/跨层 | 优先路径记忆/功能记忆 |
| 文本插入符 | 方向键移动选择 |

## 五、光标与焦点对比

### 5.1 核心差异

| 维度 | 光标 | 焦点 |
|------|------|------|
| 移动方式 | 摇杆=光标移动 | 摇杆=方向移动 |
| 界面限制 | 无 | 有，需线性布局 |
| 自由度高 | 高 | 低 |
| 主机适配 | 差 | 好 |

### 5.2 混合模式

```
趋势：光标+焦点结合

触发规则：
├── 光标瞬移到焦点位置[推荐]
├── 光标保持原位
└── 光标置于画面中心
```

### 5.3 模式选择

```
基于PC开发 → 光标+焦点辅助 / 纯光标
基于主机开发 → 纯焦点
```

## 六、设计决策框架

```
开发流程 ───────────────────────┐
                                 │
    PC端设计 ──→ 主机移植        │
         ↓                       │
    关键问题 ──→ 解决时机        │
         ↓                       │
    功能阻塞 ──→ 需求阶段反馈    │
                                 │
适配策略选择 ────────────────────┘
       │
       ├─→ 功能简单 → 完全一致
       ├─→ 主流场景 → 基本一致
       └─→ 差异过大 → 重构
```

## 总结

| 设计维度 | 核心问题 | 解决方案 |
|----------|----------|----------|
| **双端策略** | 功能复杂度差异 | 基本一致为主 |
| **PC布局** | 兼顾主机易用 | 线性排列+部件集中 |
| **主机走焦** | 焦点移动规则 | 就近+十字+记忆三原则 |
| **键位适配** | 操作便利性 | 约定俗成映射+一致性 |
| **TRC合规** | 索尼技术规范 | 安全区+加载+用户名等 |

**最终目标**：让主机玩家感受"简洁但不简单"的流畅交互体验。
